## The one file

| | |
|---|---|
| File | `supabase/migrations/202610060001_review_fit.sql` |
| What it does | adds `reviews.fit` (`'small' \| 'true' \| 'large'`) plus a partial index on `reviews (product_id) where fit is not null` |
| Unlocks | the "ছোট / ঠিক / বড়" tap on the review form and the **"Will it fit me?"** bar on the product page (the size/fit pass) |
| If you skip it | nothing breaks. `POST /api/reviews` retries the insert without `fit` when Postgres reports the column missing, so reviews keep coming in — the fit bar simply never appears, because there is no data to show |
| Safe to re-run? | yes — `add column if not exists` + `create index if not exists`. Run it twice and the second run changes nothing |

### How

Supabase Dashboard → **SQL Editor** → paste the whole file → **Run**. It is one
`begin; … commit;` transaction; if it times out, run it again.

With the CLI instead: `supabase db push` (it picks up `supabase/migrations/`),
or `psql "$DATABASE_URL" -f supabase/migrations/202610060001_review_fit.sql`.

### How to know it worked

`/api/health` now reports it. With a staff session (or the `x-health-token`
header) the report includes:

```json
{ "reviewFitReady": true }
```

…and while it has not run, `nextSteps` names the file and explains what is
waiting on it. The probe is a `select fit from reviews limit 1`, so it answers
from the live database — no SQL access needed to check.
