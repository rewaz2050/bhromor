## 2. Findings — severity onujayi

### 🔴 HIGH

**H1. `memberships` table-e RLS enable-i kora hoy nai → anon key diye sobar phone/trxid pora + status change kora jay**
- File: `supabase/migrations/202609140015_plus_membership.sql` (policy create kora ache, kintu `alter table memberships enable row level security` line **nai**; `bootstrap-fresh.sql`-eo nai)
- Evidence (PGlite, role `anon`): `SELECT` → sob row dekha jay (phone, trxid); `UPDATE ... set status='active'` → 1 row affected.
- Browser bundle-e `NEXT_PUBLIC_SUPABASE_ANON_KEY` thake, tai je keu PostgREST diye direct hit korte pare — app code (`src/lib/db/membership.ts`) service-role use kore, tai app nijer path diye nirapod, kintu table ta khola.
- Verify (Supabase SQL editor): `select relrowsecurity from pg_class where relname='memberships';` → `false` hole confirmed.
- Fix (1 line): `alter table memberships enable row level security;` (+ bootstrap mirror).

**H2. 8 ta SECURITY DEFINER write-function-e kono auth guard nai, ar explicit `revoke execute` o nai → default grant-e anon/authenticated call korte pare**
- Functions: `ps_place_order`, `ps_use_coupon`, `ps_book_delivery_slot`, `ps_return_action`, `ps_assign_batch_to_rider`, `ps_credit_referrer`, `ps_expire_stale_offers`, `ps_shop_rating_recompute` (`supabase/bootstrap-fresh.sql` L591, L1900, L3499, L3596, L4663, L4904, L6439, L6659)
- Shudhu `ps_checkout_health` e `revoke ... from anon, authenticated` ache (L7297). Baki gulor `proacl = NULL` → Supabase default = anon+authenticated EXECUTE.
- Practical impact:
  - `ps_book_delivery_slot(date, window)` — kono secret lage na → 20 call-e jekono din-er slot **full** kore deya jay (scheduled delivery DoS). PGlite-te verified: anon ×20 → `booked_orders 20/20`.
  - `ps_use_coupon(uuid)` — anon ×3 → `used=3`, coupon shesh (coupon uuid lage, jeta public API deyna — tai risk lower).
  - `ps_place_order` — API-r rate-limit/validation bypass kore direct order insert kora jay (function nijer zone/product/coupon check kore, kintu spam thamay na).
  - `ps_return_action(order uuid, 'approve'|'reject')` — vendor/jar kache order uuid ache se jekono order-er return approve/reject korte pare.
- Verify: `select proname, proacl from pg_proc where proname like 'ps_%' and prosecdef;` → `NULL` mane default grant.
- Fix: protita function-e `revoke all on function ... from public, anon, authenticated; grant execute ... to service_role;` (app sob RPC service client diye kore — `grep -rn '.rpc("ps_' src` confirm korechi, tai kichu bhangbe na).
