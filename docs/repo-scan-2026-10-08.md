# Whole-repo scan — what is broken, mismatched or missing (2026-10-08)

Method: static analysis (link graph, API contract, public assets, env vars,
DB schema vs code, doc paths) plus a **live crawl of a production build** —
87 page routes and 178 API routes against `next start`.

**Verdict: 6 real problems, all of them about what happens when something is
NOT there** (a missing page, a missing record, a thrown error). The happy path
was already clean: every route answers, no broken links, no missing assets, no
column mismatches, no crashes in the server log.

**All six are fixed** (below). Two things the scan flagged turned out to be
false alarms — they are listed at the bottom, because a scan that only reports
what it got right is worth less than one that says where it was wrong.

---

## 1. Every 404 was a soft 404 — HTTP 200 (site-wide)

| URL | Before | After |
|---|---|---|
| `/this-page-does-not-exist-xyz` | 200 | **404** |
| `/product/ghost` (no such piece) | 200 | **404** |
| `/shops/nope` | 200 | **404** |
| `/shops/nope/p/ghost` | 200 | **404** |
| `/admin/nonexistent-page` | 200 | **404** |
| `/vendor/x`, `/rider/x` | 200 | **404** |
| `/deep/unknown/path` | 200 | **404** |

The 404 page itself always rendered correctly; only the status was wrong, and
a status is what link checkers, monitoring and Search Console read. Next does
inject `<meta name="robots" content="noindex">`, so Google never indexed them
— it still reported them as **Soft 404** errors.

**Cause (documented, and now proven by experiment):** Next returns 404 only
*before* streaming starts; a `loading.tsx` makes the shell stream immediately,
so every `notFound()` under it answers 200 with the 404 body.
`src/app/(site)/loading.tsx` sat above the entire storefront.

**Fix — move the skeleton off the routes that can refuse:**

- deleted `src/app/(site)/loading.tsx` (it covered every storefront route);
- deleted `product/[slug]/loading.tsx` and `shops/[slug]/p/[product]/loading.tsx`;
- the homepage and the `/shops` listing kept theirs by moving into route
  groups — `(site)/(home)/` and `(site)/shops/(list)/` — so the boundary
  belongs to those pages only and not to their children;
- added `offers/loading.tsx` (a listing that always exists has no status to lose).

Ruled out along the way: it was **not** the proxy (still 200 with `proxy.ts`
removed), **not** `vercel.json` (no rewrites), and **not** the layout reading
cookies.

**Trade-off, stated:** a product or shop page no longer shows an instant
skeleton — it resolves its (cached) row first, which is what lets it answer a
real 404 when the row is not there. Listings keep theirs.

**Guarded so it cannot come back:** `src/app/__tests__/not-found-status.test.ts`
asserts that no `loading.tsx` exists above the three refusable routes (the
unit suite cannot see a status code, so the file placement is what it checks),
and `e2e/storefront.spec.ts` asserts the status codes themselves.

## 2. The storefront catch-all swallowed unknown `/api/*` paths

`/api/nope` returned the 404 **HTML page** with a 200, so
`fetch("/api/typo").then(r => r.json())` threw `Unexpected token '<'`.

**Fix:** `src/app/api/[...missing]/route.ts` answers `{"error":"No such
endpoint."}` with a JSON 404 on every method. Real routes still win over a
catch-all, so nothing is shadowed. Verified: `/api/nope` and
`/api/really/deep/miss` → `404 application/json`.

## 3. No error boundary outside `/admin`

A thrown server error on the storefront, in the rider app or in the vendor app
fell through to Next's bare production screen — no chrome, no way back, on a
phone mid-delivery.

**Fix:** one shared bilingual screen (`src/components/ui/error-state.tsx`),
used by new `src/app/error.tsx` (app-wide), `src/app/global-error.tsx` (catches
a root-layout failure, so it renders its own `<html>`/`<body>`), and dedicated
`rider/error.tsx` and `vendor/error.tsx` so each keeps its own way home.
`/admin` keeps its own, which also offers "sign in again".

## 4. The 404 page borrowed the homepage's `<title>`

```
before: <title>PROSANTI — Rooted in Bangladesh. Designed for Today.</title>
after:  <title>Page not found · PROSANTI</title>
```

Both `not-found.tsx` files now export their own metadata (with `noindex`).

## 5. No CI

`.github/workflows/` held only `cron.yml`, so nothing ran lint, typecheck or
the 3,460-test suite on push or PR — Vercel catches a broken build, nothing
catches a broken test.

**Fix:** `.github/workflows/ci.yml` — `npm ci` → lint → typecheck → test →
build, on pushes to `main` and on every pull request, Node 22. Playwright
stays opt-in: it needs a seeded backend and a browser.

## 6. Doc drift

Two genuinely stale references in `README.md` (a deleted `src/lib/db/auto-seed.ts`
described as current architecture, and a moved test path) — both corrected.

## Where the scan was wrong

- **"4 env vars missing from `.env.example`" — false alarm.** The scanner only
  read *uncommented* `NAME=` lines. `CRON_SECRET`, `HEALTH_TOKEN`,
  `NEXT_PUBLIC_SITE_URL` and `PUSH_VAPID_SUBJECT` are all there, documented as
  optional (commented out). Re-checked: nothing the code reads is undocumented
  except `NODE_ENV` and the two `VERCEL_*` variables, which the platform
  provides. The five vars in `.env.example` that no code reads (`TWILIO_*`,
  `PATHOA_*`) are labelled "future phases only" — deliberate, not drift.
- **`src/middleware.ts` cited in `BUGFIXES.md` and the 2026-09-16 audit —
  false alarm.** Both are historical records of the Next 16 rename to
  `src/proxy.ts`; the old name is the point of the sentence.

## Verified clean — do not go looking here

- **All 87 page routes answer, and the 4 that should 404 now do** (83 × 200 +
  4 × 404). No error markers (`Application error`, `__next_error__`, `NaN`) in
  any response, and zero stack traces in the server log across the crawl.
- **No broken internal links.** 68 `href="/…"` and 7 `router.push`/`redirect`
  targets all resolve to a real route.
- **No API contract mismatches** — every `fetch("/api/…")` has a route and a
  method the route exports; no 404s, no 405s.
- **All referenced static assets exist.** Manifest, robots, sitemap, favicon,
  icons, `sw.js` and all four `opengraph-image` routes serve 200 with the
  right content type (real PNGs, 52–612 KB).
- **DB schema matches the code** (schema.sql + 108 migrations + bootstrap).
  The 39 apparent misses were parser artifacts: multi-line `add column`,
  embedded selects like `customers (id, name, phone)`, and `v_product_sales`,
  which is a **view**.
- **No hardcoded secrets**, only 3 `dangerouslySetInnerHTML` (2 JSON-LD + the
  pre-paint language script), no TODO/FIXME, 4 empty `catch` blocks, and zero
  build warnings.

## Still not verifiable in this sandbox

- **24 API routes answer 503 here** (no Supabase env) — the documented
  "unconfigured backend" path, not a defect. The data paths were therefore not
  exercised; re-run the crawl against production to confirm they answer 200.
- **Content correctness** on catalog pages: the catalog is empty here.
- **Browser console / hydration warnings**: Chromium cannot be downloaded in
  this sandbox, so Playwright never ran. The new e2e assertions above are
  written but unexecuted.
