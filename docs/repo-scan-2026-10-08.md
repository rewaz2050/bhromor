# Whole-repo scan — what is broken, mismatched or missing (2026-10-08)

Method: static analysis (link graph, API contract, public assets, env vars,
DB schema vs code, doc paths) plus a **live crawl of a production build** —
87 page routes and 177 API routes against `next start`.

**Verdict: 7 real problems, all of them about what happens when something is
NOT there** (a missing page, a missing record, a thrown error). The happy path
is clean: every route answers, no broken links, no missing assets, no column
mismatches, no crashes in the server log.

---

## 1. Every 404 is a soft 404 — HTTP 200 (site-wide)

| URL | Expected | Actual |
|---|---|---|
| `/this-page-does-not-exist-xyz` | 404 | **200** |
| `/product/ghost` (no such product) | 404 | **200** |
| `/shops/nope` | 404 | **200** |
| `/admin/nonexistent-page` | 404 | **200** |
| `/vendor/nonexistent-page` | 404 | **200** |

The not-found page itself renders correctly; only the status code is wrong.
Next does inject `<meta name="robots" content="noindex">`, so Google will not
index them — but Search Console still reports them as **Soft 404** errors,
uptime and link checkers stay green, and no monitor can ever tell you a link
broke.

**Cause (documented, not a code mistake):** `notFound()` returns 404 only
*before* streaming starts; after it starts the status stays 200 and only the
body is swapped ([Next docs](https://nextjs.org/docs/app/api-reference/file-conventions/not-found)).
Every storefront route streams — there are 8 `loading.tsx` files and the
layouts are dynamic — so the 200 shell is on the wire before anything can
refuse.
Ruled out by experiment: it is **not** the proxy/middleware (still 200 with
`src/proxy.ts` removed) and **not** `vercel.json` (no rewrites).

**Fix:** Next 16's `app/global-not-found.js` (experimental) handles unmatched
URLs at the *routing* level, skipping rendering — that fixes the unknown-URL
case outright. For known routes with a missing record (a product slug that has
no product), the existence check has to move above the streaming boundary
(into the page before any Suspense, or into `proxy.ts`), or the route must not
stream.

## 2. The storefront catch-all swallows unknown `/api/*` paths

`curl -i /api/nope` → **200, `text/html`** — the storefront's 404 page, not a
JSON 404.

`(site)/[...missing]` sits at the root of the app (route groups add no path
segment), so it claims every unmatched path in every surface, `/api/*`
included. Any client `fetch("/api/typo").then(r => r.json())` therefore throws
`Unexpected token '<'` instead of surfacing a 404.

## 3. No error boundary outside `/admin`

`find src/app -name error.tsx` → **only `src/app/admin/error.tsx`**. There is
no root `src/app/error.tsx` and no `global-error.tsx`.

So on the **storefront, the rider app and the vendor app**, any thrown server
error — a Supabase timeout, a row the mappers did not expect — shows Next's
raw production page (*"Application error: a server-side exception has
occurred"*): no header, no footer, no way back. Rider and vendor are used in
the field, on phones, mid-delivery.

## 4. The 404 page's `<title>` is the homepage's

Neither `src/app/not-found.tsx` nor `src/app/(site)/not-found.tsx` exports
`metadata`, so:

```
$ curl -s /this-page-does-not-exist-xyz | grep -o '<title>.*'
<title>PROSANTI — Rooted in Bangladesh. Designed for Today.</title>
```

Tabs, history and share sheets label the 404 as the homepage. Two lines of
`export const metadata = { title: "Page not found" }` in each file fixes it.

## 5. No CI

`.github/workflows/` contains **only `cron.yml`** (the shop clock). Nothing
runs `npm run lint`, `npm run typecheck`, `npm test` (3,450 tests) or
`npm run build` on push or PR, and there are no pre-commit hooks. Vercel runs
the build on deploy, so a broken build is caught — a broken test is not.

## 6. Four env vars are used but missing from `.env.example`

`CRON_SECRET`, `HEALTH_TOKEN`, `NEXT_PUBLIC_SITE_URL`, `PUSH_VAPID_SUBJECT`.

The guards themselves are sound — `/api/cron/tick` answers 503 with
`configured: false` when `CRON_SECRET` is unset and compares it in constant
time, and `/api/health` requires staff. The gap is that a fresh deployer who
copies `.env.example` gets a shop whose clock never ticks, with no hint why.

## Verified clean — do not go looking here

- **All 87 page routes answer 200.** No error markers (`Application error`,
  `__next_error__`, `NaN`, …) in any response, and **zero stack traces** in
  the server log across the whole crawl.
- **No broken internal links.** 68 `href="/…"` and 7 `router.push`/`redirect`
  targets all resolve to a real route (dynamic segments matched).
- **No API contract mismatches.** Every `fetch("/api/…")` has a route file and
  a method the route exports — no 404s, no 405s.
- **All referenced static assets exist** (6/6). `/manifest.webmanifest`,
  `/robots.txt`, `/sitemap.xml`, `/favicon.ico`, `/icon.png`,
  `/apple-icon.png`, `/sw.js` and all four `opengraph-image` routes serve 200
  with the right content type (the OG routes paint real PNGs, 52–612 KB).
- **DB schema matches the code.** Every column the code selects is defined in
  `supabase/` (schema.sql + 108 migrations + bootstrap). The 39 apparent
  misses were all parser artifacts: multi-line `alter table … add column`,
  embedded selects like `customers (id, name, phone)`, and `v_product_sales`
  which is a **view**, not a table.
- **No hardcoded secrets** (no `sk_live`, `AKIA`, `ghp_`, PEM blocks).
- **Only 3 `dangerouslySetInnerHTML`** — two JSON-LD blobs and the pre-paint
  language script.
- **No TODO/FIXME/HACK**, 4 empty `catch` blocks, and **zero build warnings**.

## Not verifiable in this sandbox

- **24 API routes answer 503 here** (`/api/products`, `/api/zones`,
  `/api/track`, `/api/orders`, `/api/contact`, …) because there is no
  Supabase env. That is the documented "unconfigured backend" path, not a
  defect — but it does mean the data paths were **not** exercised. Re-run the
  crawl against production to confirm they answer 200.
- **Content correctness** on catalog pages: the catalog is empty here, so
  empty states could not be judged.
- **Browser console / hydration warnings**: Chromium cannot be downloaded in
  this sandbox, so Playwright could not run and no real browser ever loaded a
  page. The hydration-mismatch class was checked statically only.
