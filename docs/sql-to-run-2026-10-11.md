# SQL to run — 2026-10-11

**Two files. Both optional, and both fail loudly-but-safely if you skip them.**

1. `supabase/migrations/202610110001_customer_addresses.sql`
2. `supabase/migrations/202610110002_customer_threads.sql`

Everything else in this pass — the shop name in the order history, the rider
card, the tracker and dashboard re-reading themselves — is pure code and needs
nothing from the database.

---

## 1. `202610110001_customer_addresses.sql`

| | |
|---|---|
| What it does | adds `customer_addresses` — the address book, mirrored on the server |
| Unlocks | a saved address following the customer to their next device. Today it lives in `localStorage` and the account page says so out loud |
| If you skip it | nothing breaks. `/api/account/addresses` answers `501 missing_table`, the browser copy keeps working exactly as it does now, and the account page prints "এখন শুধু এই ব্রাউজারে আছে—অন্য ডিভাইসে যাবে না" |
| Safe to re-run? | yes — `create table if not exists` + `create index if not exists` |

## 2. `202610110002_customer_threads.sql`

| | |
|---|---|
| What it does | adds `customer_threads` + `customer_messages` — the in-app conversation between a shopper and the shop |
| Unlocks | "দোকানকে বার্তা দিন" on the tracker, the **বার্তা** tab on the account, and **Messages** in the vendor panel |
| If you skip it | nothing breaks. Every route answers `501 missing_table`, and each UI says which file to run instead of showing a broken list. The WhatsApp button is untouched and still the fastest route |
| Safe to re-run? | yes — `create table if not exists` + `create index if not exists` |

Both are service-role only: row level security is enabled with **no policies**,
so `anon` and `authenticated` get nothing and only the API routes — behind the
customer session or the vendor/staff check — can read them.

### How

Supabase Dashboard → **SQL Editor** → paste the whole file → **Run**. Either
order; they do not depend on each other.

With the CLI instead: `supabase db push`, or
`psql "$DATABASE_URL" -f supabase/migrations/202610110001_customer_addresses.sql`.

### Checking it worked

```sql
select table_name from information_schema.tables
where table_schema = 'public'
  and table_name in ('customer_addresses', 'customer_threads', 'customer_messages');
```

Three rows means both files ran. `/api/health` will also stop reporting them as
missing once they exist.
